왜 JAMYPG NL2SQL MCP인가?

대규모 엔터프라이즈 환경에서 AI가 안전하고 정확하게 데이터베이스를 탐색하고 쿼리할 수 있도록 설계된 독보적 솔루션입니다.

🛡️

01. 스키마 환각 0% 보장

메타데이터를 인메모리 카탈로그, 지표 사전, 조인 그래프로 미리 컴파일합니다. LLM이 존재하지 않는 테이블이나 컬럼을 추측해 쿼리를 생성하는 문제를 근본적으로 방지합니다.

⚡

02. Pure Go 멀티 DB 엔진

PostgreSQL(pgx/v5), MySQL 8.x, MariaDB 10/11을 CGO나 클라이언트 라이브러리 없이 순수 Go 드라이버로 지원하며, 세션 수준 Read-Only 옵션을 강제 적용합니다.

🛠️

03. 85개 이상의 MCP Tools

prepare_sql_context를 포함한 NL2SQL 파프라인부터 DBA 헬스 점검(db_health_report), 인덱스 추천(suggest_indexes), 워크로드 집계(workload_report)까지 폭넓은 도구를 제공합니다.

🔄

04. Self-Healing 피드백 루프

반복되는 쿼리 실패 패턴 및 교정 이력을 감지하여 learned_rules.json으로 자동 승격시킵니다. 시스템을 사용할수록 NL2SQL 정확도가 지속적으로 향상됩니다.

🖥️

05. 내장 Web Admin & REST API

브라우저에서 데이터셋과 테이블 그리드를 인라인 수정(/admin/editor)하고, DBA 콘솔, DB 연결 관리, Swagger UI (/docs) 및 OpenAPI 3.0 스펙을 즉시 활용할 수 있습니다.

🌐

06. OpenMetadata 연동

OpenMetadata와 논리명, 설명, PII 태그, 용어집 및 테이블 Lineage 엣지를 양방향으로 동기화하고 Drift 대조 리포트를 생성하여 메타데이터 거버넌스를 완성합니다.

권장 워크플로

안전하고 표준화된 NL2SQL 생성 6단계

LLM이 직접 SQL을 오케스트레이션하지 않고, JAMYPG의 가이던스를 따라 안전하게 처리되는 6단계 프로세스입니다.

1
질문 분석 & 컨텍스트 취득
사용자의 자연어 질문을 분해하여 의도(Intent), 지표, 차원, 시간 범위 및 리터럴 필터 컬럼을 매핑합니다.
prepare_sql_context(question)
2
모호성 확인 & 되묻기 (Clarification)
응답 status가 needs_clarification인 경우, 임의로 판단하지 않고 사용자에게 명확한 기준을 되묻습니다.
status: "needs_clarification"
3
SQL 골격 조립 (Skeleton Construction)
조인 그래프, 지표 식, 시간 변환 조건이 적용된 SQL 골격을 생성하며, LLM은 /* SLOT */ 주석 위치만 채웁니다.
build_sql_skeleton / skeleton_sql
4
정적 검증 & 린팅 (Validation & Linting)
타겟 DB 방언(postgres/mysql/mariadb) 규칙, GROUP BY 정합성, 카티션 조인 유무, PII 데이터 포함 여부를 다각도로 검증합니다.
validate_sql(sql, expected_outputs)
5
실행 계획 & 리스크 분석 (Explain & Risk Check)
실제 DB의 EXPLAIN (FORMAT JSON)을 수행하여 Full Table Scan, 대량 정렬 등 고비용 쿼리 위험을 사전에 차단합니다.
explain_sql(sql, profile)
6
Read-Only 안전 실행 & 자기 수정
강제 Read-Only 트랜잭션, 타임아웃, 최대 행 제한 가드 환경에서 실행하고, 오류 발생 시 execute_with_repair로 원턴 교정을 진행합니다.
run_sql_safely / execute_with_repair
호환성 & 보안

지원 데이터베이스 & Read-Only 세션 가드

별도의 CGO 빌드 환경이나 클라이언트 SDK 설치 없이 바이너리 하나로 주요 3개 관계형 DB를 완벽 지원합니다.

데이터베이스 프로파일 type Go 드라이버 Read-Only 세션 강제 상태
PostgreSQL (9.6 ~ 16+) postgres (기본) pgx/v5 (pure Go) default_transaction_read_only=on 공식 지원
MySQL (8.x) mysql go-sql-driver/mysql transaction_read_only=1 공식 지원
MariaDB (10.x / 11.x) mariadb go-sql-driver/mysql tx_read_only=1 공식 지원
MCP 스펙

엔터프라이즈 MCP Tools 카탈로그

LLM AI 에이전트가 데이터베이스 탐색, NL2SQL 생성, DBA 진단 및 카탈로그 관리를 수행할 수 있는 85종의 대표 도구입니다.

prepare_sql_context

질문 분석 → 스키마 검색 → 지표 매칭 → 조인 경로 → SQL 골격을 한 번에 반환하는 권장 메인 진입점.

NL2SQL Core
validate_sql

Postgres/MySQL/MariaDB 정적 검증, 카티션 조인 감지, PII 노출 탐지 및 2회 자동수정을 위한 fix_hints 생성.

NL2SQL Core
run_sql_safely

Read-Only 세션 환경에서 타임아웃, 최대 행 제한 및 감사 로그를 적용하여 안전하게 DB 쿼리를 실행.

NL2SQL Core
search_schema

물리/논리명, 용어집, 지표, 과거 성공 쿼리 및 조인 연결성을 종합한 다중 신호 스코어링 검색.

Catalog & Schema
get_join_paths

인메모리 조인 그래프를 기반으로 테이블 간 최적 조인 경로, 신뢰도 및 금지 조인 조건을 탐색.

Catalog & Schema
db_health_report

PK 없는 테이블, 인덱스 없는 FK, 미사용 인덱스, 대형 테이블 코멘트 부재 등 DBA 진단 수행.

DBA & Diagnostics
suggest_indexes

실제 감사 로그의 느린 쿼리를 분석하여 최적의 CREATE INDEX DDL과 대표 쿼리를 제안.

DBA & Diagnostics
import_openmetadata

OpenMetadata의 논리명, 설명, PII 태그, 용어집을 수급하여 JAMYPG 카탈로그에 안전하게 병합.

Frequently Asked Questions

궁금한 점을 확인하세요 (FAQ)

JAMYPG의 동작 방식, 보안 매커니즘, AI 검색 엔진 및 LLM 연동에 관한 명쾌한 답변입니다.

Q1. 기존 Text-to-SQL 프롬프트 방식보다 JAMYPG가 뛰어난 이유는 무엇인가요?
단순 프롬프트 방식은 테이블 수십 개만 넘어가도 컨텍스트 길이를 초과하거나 존재하지 않는 테이블/컬럼/조인 관계를 지어내는 환각(Hallucination)이 발생합니다. JAMYPG는 스키마, 논리명, 지표 식, 조인 그래프를 사전 인메모리 카탈로그로 컴파일하여 필요한 압축 컨텍스트만 공급하고, build_sql_skeleton 및 validate_sql 검증을 거쳐 100% 구조적 정합성을 보장합니다.
Q2. DB 데이터 수정이나 삭제 위험은 전혀 없나요?
네, 전혀 없습니다. run_sql_safely 도구는 postgres/mysql/mariadb 드라이버 연결 시 세션 레벨에서 default_transaction_read_only=on, transaction_read_only=1, tx_read_only=1을 강제 적용합니다. INSERT, UPDATE, DELETE, DROP 등 모든 쓰기 시도는 데이터베이스 엔진 수준에서 완전히 차단됩니다.
Q3. CGO 빌드가 필요 없다는 것은 어떤 의미인가요?
과거 오라클 SDK(Instant Client) 등 C 라이브러리 의존성을 완벽히 제거하고 100% 순수 Go 드라이버(pgx, go-sql-driver/mysql)로 교체했습니다. 이로 인해 크로스 컴파일이 매우 용이하며, CGO_ENABLED=0 환경에서 크로스 컴파일된 단일 실행 바이너리 하나만으로 리눅스, 윈도우, macOS 어디서나 즉시 실행 가능합니다.
Q4. OpenMetadata 등 기존 거버넌스 도구와 연동이 가능한가요?
예, 완벽히 가능합니다. import_openmetadata 및 export_to_openmetadata 도구를 통해 OpenMetadata의 테이블/컬럼 논리명, 설명, PII 태그, 용어집 및 Lineage 정보를 양방향으로 동기화할 수 있으며 openmetadata_drift 리포트로 변경 사항을 감시할 수 있습니다.
